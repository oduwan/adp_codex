The operator explicitly superseded the earlier same-UID historical replay and
standalone net-negative-line-count gate. The historical5b32 report is retained
below; its BLOCKED_COMPLEXITY decision is not the current architecture rule.
This implementation still requires exact-HEAD focused source/security/evidence

No new permanent identity, authority record, store, journal, ref, database,
service or background process is added. The existing H3 is the single historical
basis. No ALLOW, current owner or positive permission survives an invocation.
The scope is reset on normal return and exceptions; another coordinator receives
its own independent qualification. Copied thread/process contexts refuse reuse.

For publication, the existing post-SUBMITTED dispatch binds one exact current
canonical subject, consent, claim, service, transport, target and Budget. Every
POST/CAS rechecks it with one late actual Memory inspection. Post-upload fences
cannot adopt another checkpoint. All three native M3 authorizations, both full
batch validations, fresh target/rules, exact expected-old CAS, confirmed stop,
observation and settlement remain. N+1 fitting is **not** guaranteed completion.

## Existing writer cutover

Accounting publication keeps publish2. The existing Product journal uses schema2
and product2 tokens for PR/MERGE and CI/REVIEW/CORRECT views. REPORT uses those
same view/token rules in its existing record. Completion approval is
personal-completion2; its existing schema2 lineage receipt is retained. NEXT uses
schema2/personal-next2 in its existing intent. The three common fields are
historical_basis, historical_engine and reader_engine. Ordinary personal and
signed-provider formats and external authority rules are unchanged.

Incomplete legacy or changed-reader approvals cannot reserve, dispatch or be
upgraded automatically. Completed execution results remain literal retained
observations, not current PASS. Existing effects can be observed; completed NEXT
can reconnect only to the exact originally attached successor. New NEXT after
accepted completion uses historical proof even after owner release/expiry; it
never renews the old grant. Corrected publication reuses the actual publisher,
with fresh correction binding required at new local admission. Historical
adoption uses its actual recorded post-H3 engine through the non-issuing decoder;
copy/issuance remains current-engine and live-authorized.

Completion also rechecks the freshly approved source and administration,
episode revocation, exact canonical subject and actual acceptance time under
the existing canonical mutation lock before writing its immutable receipt.
An expired or changed subject leaves no receipt. Corrected manual completion
uses the approved completion SHA, without renewing the earlier PR consent.
Protected JSON reads retain the complete opened-file length check before
decoding. This authenticates initial input without a historical byte mirror.
The non-issuing exact episode review-gate regression is retained unchanged.
An absent new runtime directory reports no started Worker and creates nothing.
Existing directories and actual receipt bytes retain their protections; missing
required historical runtime evidence still refuses cold qualification, and a
SUBMITTED assignment with missing evidence cannot dispatch again.
For a launched terminal Worker, the current bound supervisor stop receipt is
mandatory. Losing it returns UNKNOWN/stopped=False without rewriting the saved
result. A saved stopped=True flag alone cannot approve a current review.
Accounting intent uses its current local fences before native facts, then the
unchanged full genuine proof after facts and before canonical effects. This
defers one duplicate proof within that boundary; ordinary personal ordering,
M3 reauthorization and independent closing/effect observations are unchanged.

## Why remaining cold code cannot simply be deleted

`personal_read_frame` still serves Product, authority, adoption, track/history
and recovery reads. Its opened-byte/permission/size binding, closed optional-file
inventory and selector checks prevent demonstrated ABA and transient-byte
failures. Its independent final raw proof is not an object-POST replay. Removing
those hooks without equivalent direct authentication would weaken the approved
contract. H3-first loading and non-issuing literal historical ae1 decoding are
also required compatibility readers, not newly issuable authority.

The direct source/admin/index/host checks in the short fence protect mutable
facts and cannot be replaced with retained ALLOW. Remaining overlap needs an
explicit same-observation equivalence proof, not a broad cache or an assumption
that an invocation lock prevents external changes.

## Cutover deliberately remains blocked

The D2 staging gates remain closed for new accounting Product
PR/MERGE/CI/REVIEW/CORRECT, REPORT, corrected publication, completion and NEXT.
This branch does not promote them as a permanent supported product pathway.
Old rows remain literal observations; no new grant, window, nonce, intent,
history or acceptance is minted from them. The existing ordinary and signed
paths keep their prior rules.

Completing the approved cutover still needs current-reader/H3 bindings in those
existing consent views, Product2/report tokens, accounting completion and NEXT2,
including historical NEXT after owner release/expiry and observation-only legacy
recovery. Adding those writers now would increase an already positive delta;
opening the old writers would violate the approved D1 security contract. Neither
is used to claim completion.

**Stop for an operator design decision.** This is not a proof that a larger
safe refactor is impossible. It is a precise gap: no demonstrated complete
replacement/deletion plan currently meets the mandatory net reduction while
retaining the named cold consumers and compatibility obligations. The minimal
alternatives are an approved concrete cold-reader replacement plan preserving
all those protections, or an explicit decision to revise the net-source gate.
No such policy revision is inferred here. No new Issue/backlog is created.
