# Personal native Issue track — M10-C

Issue #42 adds an explicitly selected finite composition of M4 discovery,
TicketPreparer, personal publication/product flow and unchanged per-Issue
M1/M2 histories. This candidate needs independent exact-revision review and
operator integration. Genuine M8 qualification remains **NOTRUN**.

## Supported envelope

Use one owned GitHub.com repository, a clean default-branch source and isolated
feature worktrees. Select at most eight existing original Issues before the
first original Reviewer. Native dependencies must stay in that complete observed
inventory. Freeze every original identity/version/body before development.
Issue text, credentials, closure, a local draft or green CI alone grants neither
completion nor permission to admit a successor. UNKNOWN/403 is not absence.

Each Issue retains its original one-task/one-round/one-context-at-a-time window,
role limits, M1 owner and M2 counters. This is an evidence index over canonical
histories, not another authoritative READY/DONE database. Old personal v1
enrollment/run and signed-provider behavior remain available without selecting a
track. No portable-memory or Progress Guard schema migration is introduced.

The exact currently observed native merged base **must already be present in
the selected owned local source**. ADP does not fetch/import objects. A missing
commit produces `NEXT_BASE_UNAVAILABLE` before next admission or a worker. The
project owner synchronizes its ordinary source checkout, then obtains a fresh
proposal. The checkout must be clean, on the actual default ref and at that exact
SHA; an equal tree or the previous feature SHA is insufficient. This is not a
zero-intervention or universal source-synchronization claim.

## Operator protocol

Use the managed launcher already selected by the Skill. Both `adp personal`
and `adp codex … --personal` expose these verbs. Always provide the same
`--repo ABSOLUTE_SOURCE --remote SELECTED --directory ORIGINAL_PRIVATE_WINDOW`.
No installation or runtime execution follows from discovering a capability.

1. Perform the existing personal `plan`/`apply`. Before its first `run`, use
   `track-preview --track-issue 1 --track-issue 2 --track-issue 3`, then separately
   confirm `track-enroll` with those same choices, the returned `--reviewed`
   token and `--authorize-memory-write`. This freezes originals only.
2. Use the accepted separate `preview`/`run`, publication, PR/check/product-review
   and merge approvals from [the one-Issue protocol](PERSONAL_PRODUCT.md).
   The actual original Reviewer additionally assesses the complete frozen
   original, unchanged proposed clauses/paths/checks, current native graph,
   project policy and actual predecessor acceptance. Purpose-bound local receipts
   preserve that exact semantic context. Actual TicketPreparer creates an
   immutable packet before feature/Developer admission. Its
   `execution_authority=UNKNOWN` never becomes an execution grant.
3. After an actually qualified and observed merge, use `completion-preview`,
   then separately confirm `complete --reviewed TOKEN --authorize-memory-write
   --confirm-project-acceptance`. Confirm actual project acceptance, including
   any human requirement it prescribes; this cannot waive a requirement or
   fabricate an independent review/check. A waiting/manual/unqualified merge
   cannot complete a dependency.
4. Inspect `track-status`. It shows actual M4 readiness separately from native
   blockers, historical accepted completion with current merge verification,
   the unique next original needing scope/window approval, or honest blockers.
   Unreviewed work remains NEEDS_SPEC; no fresh READY judgment is invented.
5. When reporting is explicitly permitted, use `report-preview`, inspect its
   exact factual product body and obtain separate consent for `report --reviewed
   TOKEN --authorize-report --authorize-memory-write --confirm-project-rules
   --assume-administrative-quiescence`. This selects only the comment grammar.
   It grants no PR/merge, issue edit, closure, label or other mutation.
6. After ordinary project-owned source synchronization when needed, propose
   `next-preview --next-issue 2 --path ORIGINAL_REQUIRED_PATH` with the actual
   project branch/message/check choices and `--seconds` window. Separately
   confirm `next` with identical choices, `--reviewed TOKEN --setup-approved
   SETUP_TOKEN --authorize-memory-write`. It releases the reconciled completed
   previous owner and enrolls exactly this distinct original scope/window.
   It starts no worker. Use the returned private directory for a newly approved
   `preview`/`run`; its original Reviewer must still obtain READY admission.
   Repeat only after the next actual accepted completion. The track is COMPLETE
   only when every selected original has the complete accepted conjunction.

## Evidence, restart and limitations

Completion retains exact original/packet, source/tree, pinned canonical M1
checkpoint, assignment and actual independent stopped context references,
M2 state, actual #21 policy/check receipts at acceptance, explicit project
acceptance and permitted observed merge/actor/parents/tree/base/ref. Historical
verification reads these facts without restoring a released/expired owner or
claiming a new CI PASS. Required private evidence must stay available on its
supported runtime host. Missing host/stop/artifact/identity proof blocks.

Preparation revalidation authenticates the actual frozen source/policy proof.
Both current and frozen records and the compared fields are retained privately
before comparison. Only a canonical own feature creation or exact committed
intent, reobserved through the existing Git port, may explain its own ref delta.
Foreign refs, source, governance, index or remote changes remain unknown. This
historical snapshot provider has no safety adapter and grants no Git operation;
current effects still use the actual current M3/M1/M2 ports.

Next intent is durable before owner release or successor setup. Original markers,
directories, generations and windows are retained; recovery cannot select another
Issue/branch/window or reset counters. Unfinished assignments/reservations,
unconfirmed transport/process stops and uncertain external effects block next.
Read-only previews/status never launch workers or repeat a mutation.
`next-preview` returns the same retained intent after an interrupted setup, or
directs reconnect to an already enrolled successor. It cannot mint a replacement
window. Native base is checked again before/after old-owner release and before
the new original's scope/feature admission.
An existing `personal.json` is insufficient: only ENROLLED, synchronized owning
M1 state and complete matching local/shared/admission/snapshot attachments count
as completed next setup. Partial setup retains the exact original approvals and
window; no execution can start before attachment is complete. The exact local
track binding and its immutable snapshot are retained while setup is PREPARED,
before the successor can become ENROLLED. Even an independent successor without
native prerequisites cannot fall back to standalone execution after a crash.

Reporting reuses the actual M7 forge, M3 REPORT decision, original M2 guard,
durable canonical intent and exclusive one-use dispatch. One stable per-product
iteration key admits at most one comment. Missing acknowledgement reconciles to
the exact target/account/comment ID/body/marker only. Absent-after-attempt,
duplicates, partial inventory, foreign authors or changed bodies remain UNKNOWN;
never POST again blindly. `report-status` observes; it does not manufacture guard
accounting. The exact own comment's additive metadata is reconciled privately;
unrelated source/version/native-edge/comment changes still stop admission.

Native merge remains HEAD_ATOMIC_BASE_OBSERVED, not atomic-base merge. Draft
readiness remains a separately authorized external action. Automatic merge
requires current project rules and its distinct explicit delegation; credentials
and CI never grant it. Existing personal administrative-quiescence limits remain.
Unsupported rules, source formats, missing source refs or forensic recovery stop
honestly. No daemon, pilot permission, release/deployment or automatic engineering
merge is added.
