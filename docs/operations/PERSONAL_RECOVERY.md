# Explicit accounting-expiry recovery

`ACCOUNTING_EXPIRY_CONTINUATION` is an opt-in exception for one precisely
qualified original personal/native-track Issue #1 attempt. It is not a general
`STOP_UNSAFE` bypass. Existing personal enrollments and independently signed
providers retain their previous rules. Installation grants no recovery rights.

All commands use the managed, pinned launcher. Discover the verb in `adp personal
capabilities` first. The same protocol is available as `adp codex VERB --personal`.
Pass `--repo`, `--remote`, and the original protected `--directory`. Obtain each
exact preview and a distinct operator reply before its corresponding write.
There is no handwritten JSON, new trust provider, daemon or automatic dispatch.

## Read-only observation in Codex

Use `archive-observe --request ORIGINAL_REQUEST` for a bounded, sanitized
observation. This never probes Codex, launches a worker, obtains a GitHub token,
recovers memory or writes a receipt. It returns an opaque reference, actual
stage, NOTRUN/UNKNOWN accounting, and explicitly UNKNOWN absolute stop time.
The older detailed `archive-preview` remains read-only and compatible.

The runtime authenticates machine identity, actual UID and Linux PID namespace.
Receipts in another sandbox are not equivalent. A mismatch returns
`BLOCKED_RUNTIME_HOST_CONTEXT`; inaccessible evidence remains blocked. Do not
edit permissions, spoof identity, copy evidence, use `sudo`/`nsenter`, or replace
the runtime. The supported native route is the Codex client's own shell tool
with **separate explicit approval to execute this exact read-only managed
command on the original host**, if that client and its managed policy provide
it. Use the tool's native approval/outside-sandbox parameter, never a shell
escape or a new service. The command must still authenticate the actual host.
Some clients cannot supply the original PID namespace even after approval.
In that case return BLOCKED; there is no portable promise or fallback that
weakens the check. Host observation consent grants no archival or run authority.

No live M8 observation or execution is authorized by engineering qualification.
The earlier sandbox failure's historical exact input remains UNKNOWN unless
retained original evidence proves it; the host-identity failure boundary itself
is deterministic and covered by disposable negative controls.
